# 江西区域化改造设计文档

## 1. 背景

当前交付目录 `D:\项目\JiangXi\YunNan_prechange_20260703_223508` 已完成恢复、构建验证、容器启动和浏览器联调，但真实验收结果表明，该系统仍然默认运行在云南口径下，而不是江西口径下。

已经确认的现状包括：

- 用户已明确纠正：`miner/server.js` 的默认图斑源应视为 `D:\项目\江西数据\Jiangxi_NaturalMine.kmz`，而不是 `yunnan.kml`
- `backend` 中多个分析与迁移入口也应按同一口径对齐到 `D:\项目\江西数据\Jiangxi_NaturalMine.kmz`，不再以 `miner/yunnan.kml` 作为当前默认事实
- 项目迁移逻辑默认区域为 `云南省`
- 工作台和地图页的默认项目与筛选项仍表现为云南/大理相关内容
- 在线卫星底图已可以切换，但“研究区域是否是江西”本质上取决于默认业务数据和默认项目口径，而不只是底图本身
- 用户已明确要求：默认图斑数据应从 `D:\项目\江西数据` 读取，而不是继续沿用 `yunnan.kml`
- 当前 `D:\项目\江西数据` 目录中已发现多种江西源数据格式
- 已确认权威默认矿山图斑源为 `D:\项目\江西数据\Jiangxi_NaturalMine.kmz`

因此，这一轮改造的目标不是简单替换地图底图，而是把系统默认运行口径从“云南版本”切换成“江西版本”。

## 2. 目标

本次改造的目标是让系统在默认启动后，表现为一个江西研究区域版本，满足以下标准：

- 默认业务数据源统一并固化为从 `D:\项目\江西数据\Jiangxi_NaturalMine.kmz` 读取江西研究区域图斑
- 默认项目区域、项目名称、迁移结果和筛选项体现江西口径
- 地图页面默认展示江西区域，并支持在线卫星底图
- 工作台、地图页、联动路径和验收文档中不再暴露云南默认口径

本次改造采用“默认口径江西化”的策略，即把当前系统固化为江西默认版本，而不是立即抽象成多省切换平台。

## 3. 非目标

本次改造不包含以下内容：

- 不在这一轮实现多省份动态切换能力
- 不在这一轮完成单独瘦身镜像打包
- 不新增与江西区域化无关的新业务功能
- 不为所有历史云南数据保留双运行模式，除非该兼容性对当前交付有明确必要

## 4. 总体思路

江西区域化必须以“数据源替换”为起点，而不能只从页面文案入手。原因是当前工作台、地图筛选项、统计图表、项目列表和迁移结果，都是围绕默认业务数据源和默认迁移逻辑生成的。

因此，改造顺序应为：

1. 切换默认业务数据源与分析入口
2. 切换项目迁移与默认区域口径
3. 切换地图视图、筛选项和页面表现
4. 统一文案、测试样例和验收文档

这样可以确保最终用户看到的江西口径，与后端实际读取的数据和项目记录保持一致。

## 5. 影响范围

### 5.1 数据入口层

以下位置需要统一核对并固化为同一个江西默认图斑源：

- `miner/server.js`
- `backend/applications/project_hub/legacy_migration.py`
- `backend/applications/kml_roi/service.py`
- `backend/kml_roi_infer.py`
- `backend/applications/interface/analysis.py`

本次改造后，这些入口都需要统一指向 `D:\项目\江西数据\Jiangxi_NaturalMine.kmz`，避免出现某些链路仍引用旧云南数据、而另一些链路已经切到江西数据的分裂状态。

### 5.2 项目化与迁移层

以下逻辑需要从云南默认口径切换为江西默认口径：

- 默认迁移项目名称
- 默认项目区域值
- 历史项目绑定与导入说明
- 默认矿山快照和数据集快照描述

重点位置是：

- `backend/applications/project_hub/legacy_migration.py`
- `backend/migrate_legacy_project_data.py`

### 5.3 地图与前端展示层

以下位置直接影响页面中的区域表现：

- `miner/src/components/MapContainer.vue`
- `miner/src/MineMap.vue`
- `miner/src/components/*`
- `miner/src/App.vue`

其中 `MapContainer.vue` 当前默认中心点为 `[25.6, 100.2]`，明显属于云南视角。本次改造不建议仅把默认中心点改为江西经纬度，而是采用“图斑驱动视角”的方式：保留基础中心点兜底，但页面加载后优先根据江西图斑执行 `fitBounds`。

### 5.4 表现文案层

需要统一清理页面、工作台和默认项目中的云南文案，包括但不限于：

- 标题中的“云南”
- 默认项目中的“大理”“曲靖”“昆明”
- 地图筛选项和项目区域字段中的云南地名

### 5.5 测试与验收层

当前测试样例中存在大量云南口径示例，例如：

- `backend/test_project_api.py`
- `backend/test_legacy_project_migration.py`
- `miner/test/projectWorkspaceHelpers.test.js`

这些测试用例需要同步切换为江西示例，否则测试层会长期保留云南默认语义，影响后续维护与验收一致性。

## 6. 设计方案

### 6.1 默认业务数据源改造

系统需要引入一个明确的“江西默认研究区域数据源目录”，即 `D:\项目\江西数据`，作为当前交付包的唯一默认图斑入口。当前已确认的权威默认矿山图斑源为 `D:\项目\江西数据\Jiangxi_NaturalMine.kmz`。

无论采用哪种载体，都需要满足两个条件：

- 能被 `miner/server.js` 直接用于地图和统计聚合
- 能被 `backend` 的 KML/分析/迁移链路复用

由于权威图斑源为 `kmz` 格式，本次设计要求新增或固化一个统一的数据适配与归一化层，负责：

- 从 `D:\项目\江西数据\Jiangxi_NaturalMine.kmz` 读取权威江西图斑源
- 将 `kmz` 解析为系统可直接消费的标准化结构，并在需要时向其他分析链路提供统一中间结果
- 统一字段名、几何字段和区域字段
- 向 `miner` 与 `backend` 暴露一致的数据接口

### 6.2 默认项目与迁移口径改造

迁移逻辑需要从“云南省历史迁移项目”切换为江西口径，并遵循以下原则：

- 默认区域字段改为江西
- 默认项目名称使用江西版命名，或使用更中性的区域驱动命名
- 迁移后的矿山绑定、数据集和活动日志不再写出云南默认值

同时，历史迁移逻辑要保持幂等性，不因为区域口径切换而破坏原有项目化流程的可重复导入能力。

### 6.3 地图视图与在线底图改造

地图层应满足以下行为：

- 默认使用在线地图 provider，可优先选择已验证稳定的在线卫星图方案
- 页面加载后根据江西图斑自动定位到江西区域，而不是停留在云南默认中心点
- 筛选项、统计图表和详情面板均从江西数据中派生

这意味着地图“显示江西”的实现应建立在“已切到江西数据源”的基础上，而不能只靠修改 `setView()` 坐标。

### 6.4 页面文案统一改造

需要统一修改以下表现内容：

- 浏览器标题
- 登录页说明
- 工作台项目卡片默认内容
- 地图页区域说明
- 页面中所有示例项目名称和默认地名

目标是让用户在从登录到地图再到项目工作台的整个路径里，不再看到云南默认口径。

### 6.5 测试与验收改造

测试层需要同步做江西化，最低要求包括：

- API 测试样例改为江西项目和江西矿山示例
- 历史迁移测试不再依赖 `yunnan.kml`
- 测试样例与夹具需要模拟从 `D:\项目\江西数据\Jiangxi_NaturalMine.kmz` 派生出的江西标准化图斑
- 地图页和项目页端到端验收标准改成江西口径

最终验收需要覆盖以下方面：

- 默认加载的是江西数据
- 项目列表体现江西口径
- 地图筛选项体现江西地市
- 在线卫星底图能显示江西范围
- GeoView 与 Miner 联动路径不再暴露云南默认值

## 8. 风险与应对

### 风险 1：只有表层变成江西，底层仍然是云南

应对方式：

- 强制先改数据入口，再改页面表现
- 在验收时同时检查 API 返回、页面筛选项和地图范围

### 风险 2：江西数据字段与云南数据结构不一致

应对方式：

- 在数据加载层增加统一字段归一化
- 避免前后端分别兼容多套字段名

### 风险 3：测试样例不改，导致后续回归成云南口径

应对方式：

- 把 `backend/test_project_api.py` 和 `backend/test_legacy_project_migration.py` 一并纳入改造范围

### 风险 4：地图显示江西，但 GeoView 联动仍暴露云南内容

应对方式：

- 将 `3000` 与 `4000` 的联动路径纳入同一套江西验收标准

## 9. 成功标准

本次江西区域化改造完成后，应满足以下成功标准：

- 默认业务数据源统一指向 `D:\项目\江西数据\Jiangxi_NaturalMine.kmz`
- 系统默认项目区域和迁移结果为江西口径

- 测试和交付文档与江西版本保持一致

## 10. 结论

江西区域化不是一次简单的地图底图替换，而是一次“默认业务口径切换”。只有同时完成以 `D:\项目\江西数据\Jiangxi_NaturalMine.kmz` 为权威源的数据适配、迁移逻辑、地图视图、页面文案和测试样例的统一切换，当前交付包才能真正从“可运行的云南版本”变成“可交付的江西版本”。
