# 江西平台整体字号与亮度调整设计

日期：2026-07-23  
状态：待用户复核  
视觉方向：B「明显提亮」

## 1. 背景与目标

江西 Miner 与江西解译平台已经采用“生态图册 / Field Atlas”视觉语言，但当前仍存在两类问题：

- 全局背景、面板和边框整体偏暗，信息分区不够清晰。
- 两端存在较多组件内固定字号。初步静态检索发现 Miner 约 67 处、解译平台约 92 处固定 `px/rem` 字号，其中部分辅助文字只有 10–12px。

本次目标是在不改变业务功能、接口和页面结构的前提下：

1. 明显提高江西两套前端的整体亮度和文字可读性。
2. 让 Miner 与解译平台遵循同一套语义化颜色、字号和交互状态规范。
3. 保持两套前端独立构建，不增加跨项目运行依赖。
4. 在 1440×900、1280×720 和 390×844 下避免主要操作溢出或不可用。

## 2. 非目标

- 不修改云南代码、主题、容器或运行配置。
- 不调整地图底图、遥感影像、分类结果栅格的实际亮度或色彩。
- 不改动上传、推理、光谱指数、历史结果、认证或导航逻辑。
- 不进行组件目录重构、依赖升级或无关样式清理。
- 不建立江西与云南共享的 CSS 包。

## 3. 方案选择

采用“统一语义变量 + 关键组件定点修正”。

两套江西前端分别保存相同语义和相同取值的 `--jx-*` 变量：

- Miner：`miner/src/assets/base.css`
- 解译平台：`frontend/src/assets/css/theme-dark.css`

两个文件在源码层保持同步，但不会互相导入，也不会形成运行时耦合。全局变量负责背景、面板、边框、文字、状态色和基础字号；组件内覆盖全局规范的硬编码值只做必要的定点替换。

不采用以下方案：

- 只修改根字号：固定像素字号不会随根字号变化，无法解决实际小字问题。
- 逐组件重写全部样式：范围过大，容易引入布局回归，与最小改动原则不符。

## 4. 颜色系统

### 4.1 核心令牌

| 令牌 | 新值 | 用途 |
|---|---:|---|
| `--jx-bg` | `#102A33` | 页面和地图外壳背景 |
| `--jx-bg-elevated` | `#183A43` | 顶栏、侧栏、次级背景 |
| `--jx-surface` | `#204650` | 卡片、弹窗、表单面板 |
| `--jx-surface-muted` | `rgba(243, 220, 170, 0.10)` | 轻强调、悬停、禁用填充 |
| `--jx-border` | `rgba(190, 245, 215, 0.40)` | 常规边框和分隔线 |
| `--jx-border-strong` | `rgba(190, 245, 215, 0.65)` | 聚焦、选中和重点边界 |
| `--jx-text` | `#F4FBF8` | 主文字 |
| `--jx-text-muted` | `#C5D8D2` | 辅助文字 |
| `--jx-primary` | `#B8F2D1` | 主操作、选中状态 |
| `--jx-primary-hover` | `#D2F8E2` | 主操作悬停状态 |
| `--jx-sand` | `#F3DCAA` | 图册编号、流程提示 |

### 4.2 状态色

| 令牌 | 新值 | 用途 |
|---|---:|---|
| `--jx-success` | `#9CE5BB` | 成功、在线、完成 |
| `--jx-warning` | `#E9A176` | 警告、部分成功 |
| `--jx-danger` | `#F18A8A` | 错误、失败、危险操作 |
| `--jx-info` | `#A8DADD` | 信息提示 |

状态不能只依赖颜色表达，现有文字、图标或状态标签继续保留。

### 4.3 提亮边界

- 提亮对象限于应用外壳、顶栏、侧栏、面板、表单、弹窗和控件。
- 地图瓦片、遥感影像、分割结果与光谱指数预览不叠加增亮滤镜。
- 预览区周围使用更亮的边框和标题区分，不改变业务图像本身。
- 阴影透明度适度降低，避免提亮后出现厚重黑边。

## 5. 字体与字号系统

### 5.1 字体族

- 展示标题：`"Noto Serif SC", "Source Han Serif SC", STSong, serif`
- 正文与控件：`"Microsoft YaHei", "PingFang SC", "Noto Sans CJK SC", sans-serif`
- 数据和编号：`Bahnschrift, "DIN Alternate", Consolas, monospace`

Miner 当前混合使用等宽字体作为正文后备，实施时调整为与解译平台一致的正文优先级；数据字段继续显式使用数据字体。

### 5.2 语义字号令牌

| 令牌 | 桌面默认 | 用途 |
|---|---:|---|
| `--jx-text-xs` | `13px` | 标签、眉题、辅助状态；全局最小可见字号 |
| `--jx-text-sm` | `14px` | 次要说明、表格辅助信息 |
| `--jx-text-control` | `16px` | 按钮、输入框、菜单、分页 |
| `--jx-text-body` | `17px` | 正文和普通信息 |
| `--jx-text-section` | `20px` | 卡片和区块标题 |
| `--jx-text-title` | `28px` | 页面主标题 |
| `--jx-text-display` | `clamp(30px, 3.3vw, 48px)` | 登录页或工作流展示标题 |

默认正文行高保持在 1.55–1.65；按钮与输入框不通过压缩行高容纳大字号，应优先增加控件高度。

## 6. 响应式规则

### 6.1 1440×900 及更宽

- 正文 17px。
- 控件 16px。
- 小标签最低 13px。
- 页面标题 28px，区块标题 20px。

### 6.2 1280×720

- 正文降为 16px，控件保持 15–16px。
- 小标签仍不得低于 13px。
- 页面标题可降至 26px，区块标题可降至 18px。
- 优先缩减面板间距和非必要装饰，不通过继续缩小文字解决空间不足。

### 6.3 390×844

- 正文 16px，小标签最低 13px。
- 页面标题 24px，区块标题 18px。
- 顶栏次要英文、非关键徽标可隐藏。
- 多列工作流和结果卡片改为单列或横向滚动。
- 主要按钮保持可见、可点击，不允许通过缩小到 12px 以下换取单行显示。

## 7. 组件修改边界

### 7.1 Miner

全局主题首先覆盖 `miner/src/assets/base.css` 和 `miner/src/assets/main.css`。随后只检查并修正以下关键组件中的硬编码小字、旧颜色和控件高度：

- `LoginPage.vue`
- `TheHeader.vue`
- `LeftSidebar.vue`
- `RightSidebar.vue`
- `MapDashboard.vue`
- `EcologyDiagnosisPanels.vue`
- `InferenceModal.vue`
- `MineDetailModal.vue`
- `ProjectWorkspace.vue`
- `TrendReportModal.vue`

地图画布和专题图层渲染逻辑不变。

### 7.2 解译平台

全局主题首先覆盖 `frontend/src/assets/css/theme-dark.css`，并通过 `app.css` 保持 Element Plus 的令牌映射。随后只检查并修正以下关键页面和组件：

- `views/Login.vue`
- `views/Home.vue`
- `views/mainfun/Segmentation.vue`
- `views/mainfun/SpectralIndices.vue`
- `views/history/History.vue`
- `components/AsideVue.vue`
- `components/Bottominfor.vue`
- `components/ImgShow.vue`
- `components/Tabinfor.vue`
- `components/Tablogin.vue`
- 与上述页面直接相关的上传、裁剪和拖拽组件

推理请求、CPU 设备、结果目录和历史记录行为不变。

### 7.3 硬编码处理规则

- 10–12px 的业务文字原则上替换为 `--jx-text-xs`。
- 表单、菜单和按钮字号替换为 `--jx-text-control`。
- 重复出现的背景、边框和文字颜色替换为语义令牌。
- 业务图例自身具有数据含义的颜色不替换。
- 图标尺寸、地图标记尺寸和纯装饰线条不机械放大。
- 测试组件和未接入当前运行链路的历史组件不顺带修改。

## 8. Element Plus 与交互状态

解译平台继续通过 `theme-dark.css` 映射 `--el-*` 变量：

- 输入框、选择器、表格、分页、弹窗和消息提示使用新背景、边框和文字令牌。
- `hover`、`active`、`disabled`、`loading` 和 `focus-visible` 保持可区分。
- 键盘焦点继续使用 2px 主色轮廓，不用只改变背景表示焦点。
- 禁用状态保留足够对比度，但不与可点击状态混淆。

## 9. 实施顺序

1. 在两端主题入口增加并同步颜色、字号语义令牌。
2. 调整全局正文、Element Plus 映射和常用控件基线。
3. 修正 Miner 关键组件的硬编码小字与旧色值。
4. 修正解译平台关键组件的硬编码小字与旧色值。
5. 运行静态检查、单元测试和生产构建。
6. 启动江西独立栈，完成三档视口的浏览器视觉检查。
7. 验证云南目录和服务未发生变化。

## 10. 验收标准

- 江西 Miner 与解译平台呈现一致的 B 方案色调。
- 桌面默认正文达到 17px；1280 和窄屏正文为 16px。
- 可见业务文字不低于 13px；确属图标内部或第三方画布绘制内容除外。
- 顶栏、侧栏、面板和弹窗明显比当前版本明亮，层级边界清晰。
- 地图、遥感影像和结果预览不因主题调整而改变数据颜色。
- 1440×900、1280×720、390×844 下登录、导航、上传、参数设置、执行和结果查看均可操作。
- 地物分类、光谱指数、历史结果、江西单点登录和返回地图功能无回归。
- 江西构建产物不包含云南路径或运行依赖，云南工程无本次修改。

## 11. 风险与控制

- **大字号导致密集面板溢出**：通过响应式间距和布局调整解决，不继续缩小文字。
- **硬编码颜色漏改**：只清理当前运行链路的关键组件，并用静态检索复核残留。
- **图例颜色被误替换**：区分界面主题色与业务数据色，数据色保持不变。
- **两端令牌漂移**：构建测试增加核心 `--jx-*` 令牌值一致性检查，但两端仍保存独立文件。
- **提亮影响地图判读**：不对地图和预览图像使用滤镜或全局透明遮罩。

## 12. 交付内容

- 两端主题令牌及关键组件样式修改。
- 与字号、主题和响应式行为相关的测试或静态契约检查。
- 1440×900、1280×720、390×844 的视觉检查记录。
- 修改报告，明确全局可控项、组件定点修正项、未修改的业务功能和云南隔离状态。
